# P3 지시서 — 번역 제공자(Provider) + 번역 큐

발신: Opus (w6:p1) → 수신: Codex (w6:p2), Codex가 일부를 Cursor (w6:p3)에 위임

## 먼저 읽을 것
- `AGENTS.md`
- `docs/DESIGN.md` §7 번역 요청 전체 (7.1 인터페이스, 7.2 큐, 7.3 프롬프트, 7.4 키 보관, 7.5 모델 목록)

## 절대 규칙
1. lingo-patch 폴더 안의 파일만 만들고 고친다. 전역 설치 금지.
2. git 쓰기 작업 금지. `docs/` 수정 금지 (설계와 다르게 하면 보고서에 이유).
3. **테스트에서 실제 API를 호출하지 않는다.** 모든 네트워크는 주입한 `fetch` 모의 함수로 대체한다. 실제 API 키를 코드·테스트·로그에 쓰지 않는다.
4. 런타임 의존성은 `@anthropic-ai/sdk` 하나만 추가 허용 (OpenAI·Gemini·호환 제공자는 `fetch`로 직접 호출).
5. 문서 확인이 필요한 사양(모델 ID, 요청 형식)은 **공식 문서**에서 확인하고, 보고서에 확인한 URL을 적는다. 확인하지 못한 것은 추측으로 채우지 말고 "미확인"으로 보고한다.

## 목표
세그먼트 묶음을 받아 AI에 번역을 요청하고 결과를 돌려주는 계층을 만든다. 캐시 연동과 페이지 렌더링은 P4에서 한다.

## 공통 타입 (`src/providers/types.ts`)
```ts
export type ProviderId = 'openai' | 'anthropic' | 'gemini' | 'openai-compatible';
export interface ProviderConfig { provider: ProviderId; apiKey: string; model: string; baseUrl?: string }
export interface TranslateItem { id: string; text: string }   // text = 자리표시 markup
export interface TranslateRequest {
  items: TranslateItem[];
  sourceLang?: string; targetLang: string;
  glossary: GlossaryEntry[];                     // 이미 세그먼트에 등장하는 것만 걸러진 목록
  context?: { pageTitle?: string; section?: string };
  signal?: AbortSignal;
}
export interface TranslateResult { items: TranslateItem[]; usage?: { inputTokens: number; outputTokens: number } }
export class ProviderError extends Error {
  kind: 'auth' | 'rate_limit' | 'server' | 'network' | 'bad_request' | 'invalid_response' | 'aborted';
  status?: number; retryAfterMs?: number;
}
export interface TranslationProvider {
  id: ProviderId;
  translateBatch(req: TranslateRequest): Promise<TranslateResult>;
  listModels(): Promise<string[]>;               // 키 검증 겸 사용 가능 모델 조회
}
export function createProvider(cfg: ProviderConfig, deps?: { fetch?: typeof fetch }): TranslationProvider;
```
- 응답에서 빠진 id는 오류가 아니다. 결과에서 빠진 채로 반환하고, 큐가 재시도한다
- 요청에 없던 id, 형식이 틀린 JSON → `invalid_response`
- HTTP 401/403 → `auth`, 429 → `rate_limit`(`retry-after` 헤더를 ms로), 5xx → `server`, fetch 실패 → `network`, 기타 4xx → `bad_request`, AbortSignal → `aborted`

## 프롬프트 (`src/core/prompt/build.ts`)
```ts
export function buildSystemPrompt(targetLang: string): string;
export function buildUserPayload(req: Omit<TranslateRequest, 'signal'>): string; // JSON 문자열
export const OUTPUT_SCHEMA: object;  // { items: [{ id: string, text: string }] }, additionalProperties false
export function parseOutput(raw: string, expectedIds: string[]): TranslateItem[]; // 코드펜스 제거 후 JSON.parse, 검증
```
- 시스템 프롬프트 요지 (DESIGN §7.3):
  - 역할: 소프트웨어 기술 문서 번역가. 입력 JSON의 `items[].text`를 `targetLang`으로 번역
  - 원문의 모든 문장과 정보를 빠짐없이 옮긴다. 요약·생략·축약·설명 추가 금지
  - `<xN/>`, `<gN>…</gN>` 태그는 그대로 보존. 어순에 맞게 위치는 옮겨도 된다. 태그를 새로 만들거나 지우지 않는다
  - 코드 식별자, API 이름, CLI 명령·플래그, 파일 경로, URL은 번역하지 않는다
  - 용어집: `keep`은 원문 그대로, `map`은 지정한 번역어 사용
  - `targetLang`이 `ko`이면 존댓말 평서문(~합니다/~하세요)으로 쓴다. 그 밖의 언어는 공식 문서체
  - 출력은 `{"items":[{"id","text"}]}` JSON만. 다른 말 금지
- 사용자 메시지는 `{ targetLang, sourceLang?, context?, glossary?, items }` JSON
- 시스템 프롬프트는 요청마다 바뀌지 않게 한다 (프롬프트 캐싱 대비). 가변 정보는 사용자 메시지에만

## 제공자별 구현
| 제공자 | 방식 | 확인할 공식 문서 |
|---|---|---|
| anthropic | `@anthropic-ai/sdk`, `new Anthropic({ apiKey, dangerouslyAllowBrowser: true, maxRetries: 0, fetch })` (BYOK 확장이라 브라우저 직접 호출 허용 필요, 재시도는 큐가 담당) → `messages.create({ model, max_tokens: 8192, system, messages, output_config: { effort: 'low', format: { type: 'json_schema', schema: OUTPUT_SCHEMA } } })`. `temperature` 등 샘플링 파라미터와 `thinking` 필드는 보내지 않는다. `stop_reason === 'refusal'`이면 `bad_request`. 오류 분류는 SDK의 타입별 예외 클래스로 | platform.claude.com 문서 |
| openai | `fetch` → Responses API(`/v1/responses`)의 JSON schema 구조화 출력, 추론 강도는 가능한 가장 낮게. 공식 문서에서 형식 확인 | platform.openai.com/docs |
| gemini | `fetch` → `generateContent`, 헤더 `x-goog-api-key`, JSON 응답 MIME + 스키마. 공식 문서에서 형식 확인 | ai.google.dev/gemini-api/docs |
| openai-compatible | `fetch` → `{baseUrl}/chat/completions`, `response_format: { type: 'json_object' }` (스키마 미지원 서버가 많음). `apiKey`가 비어 있으면 Authorization 헤더 생략 (Ollama) | — |

`listModels`: 각 제공자의 모델 목록 API로 id 배열 반환 (anthropic은 SDK `models.list`).

## 모델 후보 (`src/providers/models.ts`)
```ts
export interface ModelOption { id: string; label: string; tier: 'high' | 'mid' | 'low' }
export const MODEL_CANDIDATES: Record<Exclude<ProviderId, 'openai-compatible'>, ModelOption[]>;
export function selectModelOptions(provider, available: string[]): ModelOption[]; // 후보 중 available에 있는 것만, 최대 3개
```
- anthropic (확정): `claude-opus-5-5` (Opus 5.5), `claude-sonnet-5-5` (Sonnet 5.5), `claude-haiku-5-5` (Haiku 5.5)
- openai (확인 필요): 사용자가 원한 것은 Sol·Terra·Luna 계열 상위 3개, **Astra 제외**. 공식 모델 문서에서 현재 API로 제공되는 정확한 ID를 확인해 후보를 정하라. Terra가 현재 세대에 없으면 그 사실을 보고하고 대안 후보(예: 이전 세대 Terra)를 제시하라
- gemini (확인 필요): 현재 안정판 중 Pro/Flash/Flash-Lite 계열 3개. 입력 가격 $5/1M 이상인 최상위 모델은 제외
- 후보에 넣은 모델마다 공식 문서 URL과 가격(입력/출력 $/1M)을 보고서에 표로

## 번역 큐 (`src/core/queue/translate-queue.ts`, 순수 로직 + 주입)
```ts
export interface QueueItem { key: string; markup: string; priority: number; tabId: number }
export interface QueueOptions {
  translate: (items: TranslateItem[], signal: AbortSignal) => Promise<TranslateItem[]>;
  maxBatchItems?: number;     // 40
  maxBatchTokens?: number;    // 2500 (estimateTokens = ceil(length / 3))
  debounceMs?: number;        // 50
  concurrency?: number;       // 3
  maxAttempts?: number;       // 3 (첫 시도 포함)
  maxMissingRetries?: number; // 2 (응답에서 빠진 항목 재요청 횟수)
  sleep?: (ms: number) => Promise<void>; random?: () => number;  // 테스트 주입
}
export class TranslateQueue {
  constructor(opts: QueueOptions);
  enqueue(item: QueueItem): Promise<string>;   // 번역된 markup
  cancelTab(tabId: number): void;              // 대기 항목은 'aborted'로 reject, 진행 중 배치는 모든 항목이 그 탭 것일 때만 abort
}
```
- 같은 key가 대기·진행 중이면 같은 Promise 반환 (중복 요청 금지)
- 우선순위 높은 순 → 들어온 순으로 배치 구성
- 재시도: `rate_limit`/`server`/`network`만. 지연 = `retryAfterMs` 우선, 없으면 1s·2s·4s × (0.8~1.2 지터). `auth`/`bad_request`/`invalid_response`는 즉시 실패
- 응답에서 빠진 항목은 다음 배치로 다시 넣고, `maxMissingRetries`를 넘으면 `invalid_response`로 실패
- id는 배치 안에서 `"0"`, `"1"`…로 새로 매긴다 (key 노출·토큰 낭비 방지)

## 필수 테스트 (모두 모의 fetch / 가짜 타이머)
- 프롬프트: 시스템 프롬프트에 보존·비요약·존댓말 규칙 포함, `parseOutput`의 코드펜스 제거·잘못된 JSON·모르는 id 처리
- 제공자 4종 각각: 정상 응답 파싱, 요청 본문·헤더 형식(키가 올바른 헤더에 실림), 401/429(retry-after)/500/네트워크 오류 분류, abort, `listModels`
- anthropic: 요청에 `temperature`·`thinking`이 없음, `dangerouslyAllowBrowser` 사용
- 큐: 배치 크기 제한(항목 수·토큰), 우선순위, 중복 key 합치기, 동시성 상한, 429 후 재시도 성공, auth 즉시 실패, 빠진 항목 재요청 후 성공 / 한도 초과 실패, cancelTab
- models: `selectModelOptions`가 available과의 교집합만 최대 3개
